# Plan: Course Search

## Goal
Wire up end-to-end search on the `/courses` page. The frontend pipeline (URL param, debounce, service param) already exists but the search input is not connected, and the backend `GET /api/courses` ignores `search`.

## Decisions
- Search matches **`title` only** (user decision), case-insensitive `ILIKE '%term%'`.
- Keep the existing plain `useState`/`useEffect` hook in `useCourses.ts` — do NOT migrate to react-query (minimal-change principle).
- Reuse the existing debounce (1000ms), URL-state, and pagination-reset behavior already in `useCourses.ts` — no changes needed there.
- Follow the product search implementation as the template (`backend/src/controllers/product.controller.ts`, `backend/src/services/product.service.ts`).

## Tasks

### 1. Backend: accept `search` in course list endpoint
- `backend/src/controllers/course.controller.ts` (`getAll`): read `const search = String(req.query.search || "")` and pass it to the service, same as `product.controller.ts:15`.
- `backend/src/services/course.service.ts` (`getAllCourses`): accept `search` param. When non-empty, add `WHERE title ILIKE $n` (pattern `%${search}%`, parameterized — never concatenated) to **both** the data query and the `COUNT(*)` query. Preserve the existing sort whitelist (`name|date|popularity`) and `LIMIT/OFFSET` params.

### 2. Frontend: wire the search input
- `frontend/src/pages/Courses.tsx` (lines ~38-51): the static `<input>` already has the correct markup. Add `value={search}` and `onChange={handleSearchChange}`, both already exported from `useCourses()` (see `useCourses.ts:83`). Mirror `pages/Product.tsx:61-62`.

### 3. Empty state
- Verify `CourseGrid` / `CourseCardList` show a sensible message when a search returns 0 results; if not, add a minimal "No courses found" empty state matching the pattern used on Products/Employees list pages.

## Out of Scope
- Migrating `useCourses` to react-query.
- Fixing the pre-existing `getById` bug (never sends the course on success) in `course.controller.ts`.
- Fixing the pre-existing camelCase/snake_case mismatch in `backend/src/models/course.model.ts` vs the seeded table.
- Searching `short_description` or other fields.

## Validation
1. Backend: `curl "http://localhost:4000/api/courses?search=react&limit=10&offset=0"` (with auth token) returns only title-matching courses and a correct `total`.
2. Search combined with `sort=name|date|popularity` and pagination still works.
3. Frontend: typing in the search box updates `?search=` in the URL after 1s debounce, resets page to 1, filters the grid and list views, and shows the empty state for a non-matching term.
4. Clearing the input restores the full list.
5. Run project checks: `tsc`/build and lint in both `frontend/` and `backend/` (use each package.json's scripts).

## Risks
- `search` must be parameterized in SQL (ILIKE `$n`), matching the product service — no string concatenation.
- Ensure the `COUNT(*)` query gets the same WHERE clause, or pagination totals will be wrong.
